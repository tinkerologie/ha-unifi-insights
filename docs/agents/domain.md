# Domain docs

## Layout

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root defines domain vocabulary.
- `docs/development/adr/` contains architecture decisions.

## Before exploring

Read `GLOSSARY.md` when it exists and ADRs relevant to the area being explored.
If a document or directory is absent, proceed silently. Create domain
documents only when needed and authorized under `AGENTS.md`.

## Vocabulary

Use glossary terms consistently in issues, proposals, code, and tests.
If a concept is missing, reconsider the wording or note the gap for
domain-modeling.

## Architecture decisions

Check each relevant ADR's status and supersession references.
Flag proposals that contradict an accepted ADR and explain the reason
before proposing a replacement.

Follow the repository's existing ADR approval, naming, and index rules.
